# 兑换码发放

在指定的群聊中，允许指定的管理员通过自然语言索要兑换码。每次发放一个**未使用**的兑换码，并把它转移到「已使用记录」、记下使用时间。一个兑换码只会被发出一次。

## 安装

在麦麦的插件市场里搜索「兑换码发放」安装，或直接把本仓库放进麦麦的插件目录：

```bash
git clone https://github.com/houlong5071/redeem-code-distributor.git
```

仓库里**不含** `config.toml`：插件首次加载时，宿主会按插件声明的默认配置自动生成它，随后在插件配置页里填写即可。这样做是为了避免把群号、QQ 号与兑换码池误提交进版本库。

## 工作原理

本插件把发码能力作为**工具**交给麦麦的大模型，由麦麦自行判断何时调用，而不是去拦截消息。插件本身相当于一份结构化的提示词：工具说明告诉麦麦什么样的请求该发码、拿到码之后该怎么处理。

这样做的直接好处是：**兑换码的发放与结果都留在麦麦的对话上下文里**，它清楚自己刚刚发过什么，不会出现「我哪来的兑换码」这种前后矛盾。

## 功能

| 配置项 | 说明 |
| --- | --- |
| **开关** | 是否启用。关闭后麦麦完全不会读取兑换码。 |
| **群白名单** | 允许使用本功能的群号（可填多个）。列表为空时任何群都不生效。 |
| **管理员白名单** | 允许领取兑换码的 QQ 号。只有这些 QQ 能触发发放。 |
| **激发信号** | 附加提示词。填写的词句会拼进工具说明，告诉麦麦本群用户惯常用哪些说法索要兑换码。**改完需重载插件生效。** |
| **兑换码池** | 一行一个兑换码，粘贴后保存即写入。 |
| **已使用记录** | 插件在发放时自动写入，含使用时间、群号与领取人，最多保留 1000 条（最新在前）。**仅在配置页可见，不会通过工具对外返回。** |
| **回复文案** | 自定义话术、兑换码前缀，以及「没有权限哦」「我的钱包都已经空了」两条回绝文案。 |
| **工具** | 是否提供余量查询工具、身份确认与兜底时间窗等参数。 |

## 行为规则

1. 只有**白名单群**里的**白名单 QQ** 才能领到兑换码，也才能查询余量。
2. 白名单群里**非白名单成员**索要时，回复「没有权限哦」（文案可改）。
3. **非白名单群**里工具仍存在，但一旦被调用会立即回绝，并要求麦麦当作普通聊天处理、不要提兑换码。
4. 兑换码发完后回复「我的钱包都已经空了」（文案可改）。
5. 每次**只发放一个**兑换码，且随机选取。
6. 发放后该码立即从未使用移到已使用记录，一个码只发一次。**写盘失败时不会发出**，避免重载后重复发放。
7. 余量查询**只返回数量**，不回显任何兑换码或领取人信息——兑换码本身就是凭据。

## 群白名单是在调用时校验的

群白名单由发码工具在每次被调用时**实时读取配置**判定，因此在配置页改完**立即生效，无需重载插件**。

> 早先的实现是用组件的 `allowed_session` 让白名单外的群"看不见"这个工具。这是错的：宿主只在**组件注册时**读取 `allowed_session`，而配置热更新不会重新注册组件。结果是改完白名单后，工具仍然挂在旧群上、新群反而看不到，且插件还会打印"配置已更新"，非常难排查。现已改为调用时校验。

工具仍然声明 `chat_scope = group`，所以私聊里不会出现。

## 权限是怎么确认的

群聊会话对象刻意不保存「最近发言人」（`MaiChatSession` 会把群会话的 `user_id` 置空），而工具调用时拿不到发起人的 QQ。插件用两条路还原身份：

1. **内存记录**：一个观察型 Hook（`chat.receive.after_process`，observe 模式）会在每条群消息到达时记下「这个会话最近是谁在说话」，带有效期（`speaker_ttl_seconds`，默认 300 秒）。
2. **数据库兜底**：内存里没有有效记录时（例如插件刚重启），回退到查询该会话最近的消息，取其中最后一条的发送者——**但必须同时满足时间窗**（`identity_fallback_window_seconds`，默认 90 秒）。

第 2 条的时间窗是必须的：群里的「最后一条消息」未必就是本次请求者。如果管理员刚说过话而内存记录又恰好失效，紧接着旁边的非管理员说一句「发个兑换码」，不加时间窗就会把他认成管理员而发码。现在最后一条消息不够新、或时间戳缺失/不可读，都会**保守拒绝**。把 `identity_fallback_window_seconds` 设为 `0` 可完全禁用兜底，身份只认内存记录。

第 2 条查询时显式传了 `filter_mai=True`，把麦麦自己发的消息排除在外——宿主该参数默认为 `False`，不排除的话，麦麦刚回复过就会把自己认成「最后发言人」，而它的 QQ 不在白名单里，兜底会稳定失败。

**关于钩子时机**：内存记录由 `chat.receive.after_process` 维护。该钩子在 `src/chat/message_receive/bot.py` 中于 `chat_manager.register_message()` **之前**触发（第 812 行 vs 第 841 行），而工具调用发生在其后的 `heartflow_message_receiver.process_message()` 链路里。因此发码工具被调用时，内存里的「最近发言人」就是刚说话的这个人，不存在读到过期发言人的问题。

两条路都拿不到身份时会**保守拒绝**，而不是放行。

发码工具与余量查询工具走的是**同一套校验**（身份 → 群白名单 → 管理员白名单）。

## 数据存放

兑换码池与已使用记录都存在本插件自己的 `config.toml` 里（`[pool]` 节），因此可以直接在插件配置页填写与查看。发放时插件会把内存状态整体写回该文件：

- 宿主对插件目录的文件监听只处理 `.py` 和 `_manifest.json`（见 `src/plugin_runtime/integration.py` 的 `_is_watchable_plugin_source`），改写 `config.toml` 不会引发全局重载；
- 回写只会定向触发本插件的 `on_config_update`，且插件内部对「自己写回的回声」做了抑制，不会把已发出的兑换码重新算回未使用；
- 写回优先在磁盘上已有的文档上就地修改，保留你在配置页里写的注释与排版；只有文件缺失或损坏时才退回用内存配置重建整份文档，以保证 `[plugin]` 等配置节不会丢失；
- **写盘失败时不会发码**：内存状态会回滚并拒绝本次发放。否则磁盘上的 `available_codes` 仍含这个码，插件重载后会再发一次；
- **陈旧保存不会让已发出的码复活**：装载池子时，已使用记录只增不减（新旧求并集），待发放池则会剔除所有已发放过的码。因此即使宿主按配置页里的旧模型整份写回、把码又带回了 `available_codes`，它也发不出去；
- 插件目录内**不会**创建任何临时文件。

### 关于「已使用记录只增不减」

这个保护带来的副作用是：**在配置页里手动删掉某条已使用记录，不会让那个码回到待发放池**。这是有意的取舍——「一个码只发一次」比「能手工回收」更重要。如果你确实需要把某个码放回池子，请换一个没用过的码，或直接编辑 `config.toml` 的 `[pool]` 节后重载插件。

当插件发现配置里的池子含有已发放过的码时，会打一条 warning 日志并在内存中剔除，配置页里看到的文本不会自动改写（下次发放写盘时才会同步）。

## 使用步骤

1. 在插件配置页打开「启用」并保存。
2. 填入「群白名单」与「管理员白名单」。
3. 在「激发信号」里填上你群里惯用的说法，例如 `发个兑换码`。
4. 在「兑换码池」里粘贴兑换码（一行一个），保存。
5. **重载插件**（仅「激发信号」属于注册期注入，需要重载；群白名单改完即时生效）。
6. 在白名单群里用白名单 QQ 说「发个兑换码」即可。

## 如果麦麦说「我没有兑换码工具」

这种回复说明**麦麦没有调用工具**，而不是工具没生效。可以按顺序排查：

1. **先确认工具确实在**：把它拉进白名单群后看配置页状态，或查日志里是否出现 `redeem_code_issue`。
2. **清一次该会话的上下文**。如果麦麦之前说过「我没有兑换码相关功能」，这句话会留在对话上下文里，它会一直沿用这个结论。用 `/clear` 清掉再试。
3. **检查「激发信号」有没有填**。这里是给大模型的提示语，写得越贴近群里的实际说法，它越容易判断对。
4. **不要被 `tool_search` 误导**。麦麦偶尔会先去 `tool_search` 搜「兑换码」，而 `tool_search` 只搜 deferred 工具——本工具是直接可见的，**不在那个池子里**，所以必然搜不到。工具说明里已明确要求它不要这么做。

需要说明的是，是否调用工具最终由大模型决定。上面几条能显著降低概率，但无法保证 100% 触发；若需要确定性触发，只能改用拦截消息的 Hook 方案。

## 已知边界

- 只支持群聊，私聊不参与发放。
- 已使用记录上限 1000 条，超出后丢弃最旧的记录（不影响已发出的兑换码）。
- 是否发放由大模型判断，因此「发个码」「来一份兑换码」这类说法通常也能触发，而精确的关键词匹配不再强制。
- 兑换码由麦麦转述给用户。插件已在工具说明中要求逐字复制，但大模型仍存在改写或漏字的小概率风险；若要求绝对逐字，需要改为由插件直接发送。
- 同理，「没有权限哦」等回绝文案也由麦麦转述，个别情况下措辞可能被润色。
- 群白名单、兑换码池、回复文案、工具开关都是即时生效；只有「激发信号」因为要注入工具描述、属于注册期行为，改动后需重载插件。
